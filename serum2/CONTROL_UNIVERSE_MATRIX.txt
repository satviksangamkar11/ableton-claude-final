Hardened inventory with evidence levels and stable identifiers

EVIDENCE LEVELS (ordered by strength):
  PROVEN_IMPLEMENTED — Control is implemented and verified to work
  PROVEN_UI_ONLY — Control exists in UI but has no persistent representation
  PROVEN_RUNTIME_ONLY — Control has VST3 HOST_PARAM but no CBOR persistence
  PROVEN_NOT_PERSISTENT — Evidence that it's not persisted despite UI existence
  UNRESOLVED — Evidence chain incomplete; investigation required

DISCOVERY STAGES (each must be independently verified):
  1. discovered-in-preset — kParam field found in factory presets
  2. proven-user-control — UI control and user interaction confirmed
  3. proven-persistent — CBOR encoding/decoding verified
  4. proven-behavioral — Effect on sound/state verified through playback/readback

For each control: ALL stages must pass before marking PROVEN_IMPLEMENTED.

ID: OSC.IDENTITY.OSC3_OSC4
Claim: Oscillator3 = SUB, Oscillator4 = NOISE
Evidence:
  1. VST3 parameters clearly labeled "Sub" (12 params) and "Noise" (11 params)
  2. Official Serum 2 docs: "Sub Oscillator" and "Noise Oscillator"
Contradictory Evidence:
  1. Oscillator3 contains container named "NoiseOsc3" (not SubOsc3)
  2. Oscillator4 contains container named "SubOsc4" (not NoiseOsc4)
  3. Preset ARP-Aardvark shows Oscillator3 plainParams with Enable/Volume
     but labeled VST3 params call it "Sub" subsystem
Confidence: UNRESOLVED — container naming contradicts VST3 naming
Status: MUST RESOLVE before implementing any SUB/NOISE controls

  1. Set Sub to distinct value

  3. Save preset
  4. Decode and observe which Oscillator{3,4} field changed
  5. Confirm mapping
