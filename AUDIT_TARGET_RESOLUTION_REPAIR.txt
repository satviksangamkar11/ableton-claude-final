================================================================================
ROOT CAUSE ANALYSIS
================================================================================

The repair script (target_resolution_repair.py) implements semantic target
resolution rules that are TOO GENERIC:

OSC1.Level rules include:
  Keywords: "level", "volume", "amplitude", "gain", "loud", "quieter", "louder"
  Patterns: r"(?:sound|output)\s+(?:quieter|louder|level)"

Problem: These keywords appear in GENERAL synthesis discussion, not parameter
  control discussion. Matching on "amplitude" in a theoretical explanation of
  oscillators is NOT the same as matching on "adjust amplitude of oscillator level".

OSC1.Detune rules include:
  Keywords: "detune", "detuning", "pitch offset", "oscillator two", etc.
  Patterns: r"detun(?:e|ing)", r"fine\s+tun(?:e|ing)"

Problem: Generic mentions of oscillator concepts are not specific target mappings.
  "The oscillators are detuned by default" is NOT the same as "here's how to
  control detune on OSC1".

Filter.Cutoff rules include:
  Keywords: "cutoff", "frequency", "brighter", "darker"
  Patterns: r"cutoff(?:\s+frequency)?"

Problem: "Frequency" is used in many synthesis contexts. "Brighter" is production
  language, not parameter documentation. These are too generic.

================================================================================
WHY THE REPAIR BROKE PREVIOUSLY VALID MAPPINGS
================================================================================

The repair script merge logic:

1. Loads all BEFORE items (including RESOLVED with valid targets)
2. Creates new_resolved dict from pattern matching on ALL items
3. Merges by: keeping all before items, THEN OVERWRITING with new_resolved
4. This means ANY item matching the new patterns gets REPLACED

The script doesn't distinguish between:
  - Items that were correctly NO_SERUM_TARGET (map these - OK)
  - Items that were correctly RESOLVED (keep these - should not change)
  - Items that were AMBIGUOUS (disambiguate carefully - not by overwriting)

Result: 43 previously RESOLVED items lost their correct targets.

   - Validate against domain-specific usage patterns
